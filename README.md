# 红果助手

Windows + 安卓的本地投屏遥控工具。红果仍在手机运行，优先通过配套「红果手机助手」显示画面并回传输入，无需 USB 或无线调试。原 ADB / scrcpy 模式保留在高级连接。非红果官方客户端，不访问红果私有接口。

项目名称为「红果助手」，Windows 程序沿用「红果遥控端」，安卓程序为「红果手机助手」。仓库：[SuperMaster-2005/hongguo_helper](https://github.com/SuperMaster-2005/hongguo_helper)。

## 启动

从 GitHub 克隆仓库或下载并解压完整 ZIP 后，无需编译或手动补运行依赖。双击 `启动红果遥控端.cmd`，或打开 `bin/HongguoRemote.exe`。保留整个项目文件夹，不要单独移动 exe。Windows 10/11 x64，需要 .NET Framework 4.8。

下载或更新项目后，首次双击 `启动红果遥控端.cmd`，或成功运行 `build.ps1`，会自动创建／更新当前用户桌面的「红果遥控端」快捷方式，指向当前目录的 `bin/HongguoRemote.exe`。之后可直接从桌面启动。移动项目后重新双击启动脚本即可更新路径。仅下载、解压或执行 Git 拉取不会自动创建；直接打开 exe 也不会创建。快捷方式创建失败会显示警告，不影响已有程序启动或构建结果。

构建输出、启动入口和快捷方式目标统一使用 `build.ps1` 中定义的程序路径。启动脚本通过 `build.ps1 -Launch` 启动；程序不存在时提示先构建并停止，不会继续尝试打开缺失的文件。

1. 把 `bin/HongguoCompanion.apk` 传到手机并安装「红果手机助手」（配套共享需要 Android 14+）。这是本地签名测试版，不是应用商店发行版；不要单独删除本地签名文件 `tools/companion-local.p12`，后续更新需要同一签名。
2. 手机开热点，电脑连接它。电脑控制可选。仅需观看时，在手机助手点「开始共享」后选「仅观看」。
3. 在系统弹窗选择「单个应用 → 红果短剧」，返回助手后确认选择。选中声音转发时会请求音频权限，仅捕获红果播放声音。
4. 电脑点击「查找并连接手机」（若发现多台，选择目标后点「开始投屏」），手机助手弹出请求时确认这是你的电脑，然后点「允许本次」。
5. 手机上打开红果，电脑直接点击、拖动；中文搜索先点手机输入框，再用电脑底部「输入文字」按钮发送。

每次新的共享需要安卓的屏幕捕获确认；每次电脑连接需要手机同意。无障碍权限通常只需首次开启，系统撤销后需重新开启。手机通知和 App 内均可停止共享，停止后连接立即失效。

侧载安装在部分手机系统上可能限制无障碍设置：如果系统明确提示「受限制的设置」，需要你自行到手机应用信息页按系统指引允许，再回到无障碍设置。具体菜单随系统版本变化。电脑端不会替你更改安全权限。热点局域网传输不依赖外网，但红果加载短剧仍需移动数据或其他互联网连接。

手机助手 0.3.11 使用 H.264 硬件编码，按原比例保留系统实际采集尺寸，最长边 3200、最短边 1440。先尝试 60 帧，按原尺寸及长边 2560、1920、1280、960 逐级回退，再尝试 30 帧。尺寸同时受编码器报告的宽高范围、宽高联动限制和对齐要求约束，不放大小尺寸源画面。只有支持 H.264 和 Surface 输入的硬件编码器参与选择；仅在编码器报告支持时指定 Baseline 配置。若编码器拒绝首选参数，会用基本 H.264 参数重试。码率按像素数和帧率计算，目标范围 6–32 Mbps，另受硬件能力限制。编码器初始化失败或运行中报错时可以降低分辨率重试，最低档 60 帧运行失败时再尝试 30 帧。电脑端解码异常会请求关键帧并重新启动解码，连接继续保留。实际网络吞吐量和源画质仍会影响观看效果。电脑端使用 tools/ffmpeg/ffmpeg.exe 解码，观看栏显示实际提交显示的帧率。音视频使用手机时间戳对齐。升级时请同时更新两端，并保留 tools 目录。清晰度下拉框只影响原调试模式。红果是否允许声音捕获、受保护内容是否黑屏，需实机确认。

0.3.11 文字输入会刷新并核对窗口和输入节点，仅允许同一红果窗口内的非密码可编辑输入框。电脑解码器管道单次写入超过 5 秒未完成时，会终止旧解码进程、请求关键帧并重新解码；手机连接保留。请同时更新电脑程序与手机 APK。

0.3.9 修复共享停止时的异常清理和网络启动／停止交错问题；即使显示或编码器释放失败，也会独立尝试停止系统共享。手机向电脑单次发送超过 15 秒未完成时会关闭连接，可重新查找连接。卸载后系统顶部共享提示是否及时消失仍需实机验证。

配套协议：UDP 24680 只回复局域网发现请求；TCP 24681 使用 TLS 1.2 传输，电脑检查发现响应中的证书指纹。首次身份发现依赖当前局域网和手机上的连接确认，没有云端账户认证；请只在你自己的热点或可信网络使用。任何屏幕和控制内容都不上传服务器。一次只接受一台电脑，未批准时不传画面或音频。

**原 USB 模式（可选）**：手机开启 USB 调试，接数据线并授权；电脑展开高级连接，刷新调试设备并选中，点击开始投屏。与手机助手模式切换时请先结束投屏。

红米 K70：设置 → 我的设备 → 全部参数与信息，连续点击 OS / MIUI 版本进入开发者模式；设置 → 更多设置 → 开发者选项 → USB 调试。如果能看不能点，检查「USB 调试（安全设置）」。不需要开启 OEM 解锁。如果连 USB 用途都没有提示，优先更换数据线和 USB 口，不要先安装来源不明的驱动。

## 操作

电脑布局以画面为中心，右侧快捷操作栏已移除。底部保留连接设置、播放暂停、返回、输入文字和全屏；连接成功自动收起左侧面板，可随时点「连接与设置」展开。窗口最小 620×440，窄窗口的连接面板覆盖在画面上，收起后画面占满可用空间。全屏隐藏头部、底部和侧栏，保留退出按钮，画面等比缩放。

手机助手使用安卓单应用共享。开启电脑控制时，另行检查红果是否处于前台。仅观看时根据系统报告的共享内容可见状态暂停和恢复，同一连接可继续使用。音频捕获限定红果 UID。电脑会根据手机报告的授权状态启用遥控。此版本需同时更新两端。

安卓 14 及以上请在系统授权时选择「单个应用 → 红果短剧」，然后在助手里确认。系统未向助手提供所选应用或采集模式的身份核验接口。误选整屏或其他应用时应取消，重新授权。原 ADB / scrcpy 模式为整屏投屏。


| 操作 | 行为 |
| --- | --- |
| 点击 / 拖动投屏画面 | 触摸 / 滑动手机 |
| 右键 | 手机返回 |
| 观看快捷键开启，画面获得焦点后 ↑↓ / 滚轮 | 发送上下滑动，不保证红果切换下一集 |
| 空格 / 播放暂停按钮 | 安卓媒体播放暂停键，实际响应由红果决定；不响应时点击手机画面的播放按钮 |
| F11 / 全屏按钮 | 主窗口全屏，未连接时也可使用 |
| Esc / 右上角退出全屏 | 恢复之前的窗口尺寸与状态 |
| 搜索、选集、收藏 | 操作手机原有界面；输入前关闭「观看快捷键」 |
| 手机助手中文输入 | 点手机输入框，再点电脑「输入文字」，会替换当前输入框文字；不写入密码框 |
| 原调试模式中文输入 | 电脑复制文字，在手机输入框聚焦后 Ctrl+V；需实机验证输入法兼容性 |

观看模式不会自动识别红果页面，打开列表或输入框时请关闭观看快捷键。正常模式不截获其他应用的键盘。投屏不自动读取手机剪贴板。手机助手模式的声音开关在手机端，电脑的声音复选框仅用于 USB / 调试模式。手机捕获到有效声音后才尝试静音。若静音后持续捕获不到声音，手机会恢复音量，本次共享保留手机声音。电脑仍可接收系统允许捕获的音频。声音失败原因会显示在手机状态和电脑诊断中。

画面尝试嵌入主窗口；若 Windows 不允许跨进程嵌入，保留独立的「红果实时画面」窗口，此时可用 scrcpy 的 Alt+F 全屏。按手机原始比例显示，不主动裁切画面。关闭程序会结束本程序的投屏进程，不退出手机红果，不关闭其他工具使用的 ADB 服务。

## 无线连接 / 手机热点

电脑与手机连同一 Wi-Fi，或电脑连手机热点。蓝牙不支持投屏。

以下为 **高级连接中的原无线调试模式**，配套 App 模式无需执行。

**自动发现无线调试设备**：

1. 手机开启无线调试，进入「使用配对码配对设备」，保持页面打开。
2. 电脑展开高级连接，点击「使用原来的无线调试连接」。发现一台手机时只显示配对码输入框；多台手机时先选择目标。
3. 输入手机上的 6 位码，点击「配对并连接」。程序自动寻找同一手机的连接服务，成功后直接选择该设备。
4. 手机上打开红果，电脑点击「开始投屏」。以后已连接的无线设备会直接识别，无需重复配对。

自动查找复用 ADB mDNS 服务发现；没有广播时，只检查当前 Wi-Fi 的唯一 IPv4 网关的 5555 端口，不扫描其他设备或端口。如果手机系统要求先连 Wi-Fi 才能开启无线调试，电脑界面不能绕过该限制。广播被隔离或只有 IPv6 服务时，自动发现可能失败，手动 IPv4 入口保留在「高级连接」。

**高级连接：手动 Android 11+ 无线调试**：

1. 手机开发者选项中开启无线调试，打开「使用配对码配对设备」。
2. 在程序展开无线连接，填弹窗中的 IPv4 地址、配对端口和 6 位配对码，点击配对。
3. 回到手机无线调试主页面，使用该页的 IP 和连接端口，点击连接。连接端口与配对端口通常不同。
4. 选中无线设备后开始投屏。热点是否能开启无线调试取决于手机系统。

**先 USB 再转无线**：

1. 先完成 USB 授权，选中 USB 设备，结束投屏后点击「USB 转无线」。
2. 输入手机当前局域网 IP:5555 并连接。热点模式可在电脑网络详情查看默认网关；同一 Wi-Fi 时查看手机 Wi-Fi 详情中的 IP。
3. 连接成功、选中无线设备后再拔 USB 开始投屏。
4. 仅在可信网络使用。用完后结束投屏，选中相应设备点击「关闭 5555，恢复 USB 模式」。Android 无线调试的开关另外在手机上关闭。

不会保存配对码。换网络或端口变化后可重新点击自动查找，手动模式则需更新连接地址。断线会停止投屏并提示，恢复连接后刷新设备再开始，不自动操作手机。

## 编译与检查

GitHub 仓库提供源码、当前 EXE/APK 和运行依赖；直接使用无需开发工具。只有重新编译安卓端才需准备 Java 17、[官方 Android SDK](https://developer.android.com/tools) 的 API 35 与 Build Tools 35。按当前脚本约定，将 API 35 的 `android.jar` 放在 `tools/android-sdk/android-35/android.jar`，将 Build Tools 35 解压内容放在 `tools/android-sdk/android-15/`。FFmpeg 与 scrcpy 已随仓库提供。首次安卓构建会生成本机签名；后续更新需自行妥善保管同一签名文件，不应提交到公开仓库。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\android\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run.ps1
```

测试脚本完成编译后，可单独运行正常解码和解码器阻塞恢复检查，不依赖 TLS 测试环境：

```powershell
.\tests\out\Tests.exe --video-only
```

安卓构建后，可用 Java 17 运行发送超时回归检查（在项目根目录执行）：

```powershell
javac -encoding UTF-8 -cp android/build/classes -d tests/out tests/AndroidWireTests.java
java -cp "tests/out;android/build/classes" local.hongguo.companion.AndroidWireTests
```

多机型尺寸与坐标映射检查使用构建后的生产类；Android SDK jar 只用于加载类型，测试不调用安卓运行时 API：

```powershell
javac -encoding UTF-8 -cp "android/build/classes;tools/android-sdk/android-35/android.jar" -d tests/out tests/AndroidCompatibilityTests.java
java -cp "tests/out;android/build/classes;tools/android-sdk/android-35/android.jar" local.hongguo.companion.AndroidCompatibilityTests
```

电脑端使用 Windows 自带 .NET Framework C# 编译器，不需要 .NET SDK 或 NuGet 包。安卓端使用 Java 17、官方 Android API 35 与 Build Tools 35，无第三方安卓运行库、Gradle 或云端构建。下载的 Google SDK 放在 `tools/android-sdk/android-35` 和 `tools/android-sdk/android-15`，编译脚本生成本地签名 APK。协议 TLS 测试需先运行安卓构建生成测试使用的证书，并在正常 Windows 用户环境执行；受限沙箱中的 Schannel 可能无法取得凭证。

## 安卓机型兼容

0.3.10 按系统和编码器能力适配，不按品牌、型号写死分辨率或权限入口。配套共享仍要求 Android 14 及以上，且系统授权界面必须提供「单个应用」选择；部分系统版本即使标为 Android 14，也需更新系统才能提供该选项。未提供时请取消授权，不选择整屏替代。

触摸优先按当前应用窗口映射；系统栏不属于共享内容时，可使用比例匹配的应用根节点区域。未知区域、旋转过程中比例不一致、窗口越出屏幕或非默认显示器上的窗口不发送触摸，避免错位操作。折叠屏尺寸计算已覆盖，折叠切换的真实系统回调仍需实机验证。

无障碍服务连接较慢时可继续等待或改为仅观看。无障碍设置入口不可用时可转到系统设置；共享授权及前台服务启动被系统拒绝时会显示原因和重试指引。旋转助手界面保留声音选择。通知权限拒绝时仍可在助手内停止共享。

以下品牌均未完成本次版本的实机验收，不能将能力检查通过视为整机兼容通过：

| OPPO／一加 | 权限返回后的服务连接、共享启动和停止 | 待实机验证 |
| vivo | 无障碍授权、后台运行限制下的断开与重连 | 待实机验证 |
| 三星 | 横竖屏、导航栏、折叠屏展开／折叠 | 待实机验证 |
| 荣耀 | 单应用共享授权、触摸位置、音频与音量恢复 | 待实机验证 |

每台设备还需按文末的配套 App 实机验收步骤检查观看、遥控、锁屏、停止、重连和持续播放。升级使用同一签名 APK 覆盖安装即可；本次不改变电脑端协议。

电脑构建、安卓 APK 构建和 v3 签名校验通过；27 项原逻辑检查与 47 项配套协议检查通过；720p60、1080p60 和 1440p60 H.264 实时解码测试（1080p 和 1440p 均覆盖横竖屏）均通过，每组 120 帧输入收到 118 帧，达到现有至少 118 帧的测试标准，并检查超限视频格式拒绝。TLS 测试为本机模拟手机端，覆盖传输和拒绝路径，不能代替 Android 实机测试。用户已确认原版本可投屏。电脑端已实际检查普通窗口、窄窗口、面板收起、F11 全屏和 Esc 恢复。TLS 等待／恢复、授权前状态拒绝及非法状态拒绝测试通过。本机另验证等待 18 秒后可在同一连接上恢复。本次 0.3.8 APK 尚未在用户 K70 上安装，红果前台识别、切出后清屏停声、回到红果恢复、单应用触摸映射、手机静音后的电脑声音、音量恢复、高清实际显示帧率、旋转和长时间播放仍待实机验收；电脑解码测试不代表手机实际达到 60 帧。受保护画面可能黑屏，应用也可能禁止声音捕获，这些限制不能绕过。

配套 App 实机验收：安装 → 授权控制 → 开始共享 → 热点发现 → 拒绝电脑连接一次 → 重新连接并允许 → 打开红果 → 切到其他应用显示等待且停声 → 回到红果恢复 → 锁屏显示等待 → 点击/拖动/返回 → 搜索中文 → 手机静音且电脑有声 → 断开恢复手机音量 → 重连 → 横竖屏及全屏 → 手机停止共享 → 重连 → 连续播放 30 分钟。任何失败请查看手机状态和电脑「使用说明与诊断」。原调试模式的 USB/无线路径单独验收。日志只在内存保留，不含配对码，不自动上传。
