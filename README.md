# 红果助手

Windows + 安卓的本地投屏遥控工具。红果短剧仍在手机上运行，电脑通过配套「红果手机助手」观看画面、接收声音并回传点击和滑动；推荐连接方式无需 USB 或无线调试。原 ADB / scrcpy 模式保留在「高级连接」中。

项目名称为「红果助手」，Windows 程序为「红果遥控端」，安卓程序为「红果手机助手」。本项目非红果官方客户端，不访问红果私有接口；登录、搜索、选集、收藏和付费均由手机上的红果处理。

仓库：[SuperMaster-2005/hongguo_helper](https://github.com/SuperMaster-2005/hongguo_helper)。当前手机助手版本为 **0.3.13**。

## 使用前准备

| 项目 | 要求 |
| --- | --- |
| 电脑 | Windows 10/11 x64，安装 .NET Framework 4.8 |
| 手机助手共享 | Android 14 及以上，系统共享授权界面必须提供「单个应用」选项 |
| 手机应用 | 已安装红果短剧，能够在手机上正常播放 |
| 网络 | 电脑连接手机热点，或两端接入可相互通信的同一 Wi-Fi；蓝牙不支持投屏 |
| 电脑运行文件 | `bin/HongguoRemote.exe`、`tools/ffmpeg/ffmpeg.exe` 及完整目录结构 |
| 手机安装包 | `bin/HongguoCompanion.apk` |
| 可选调试模式 | 另需 `tools/scrcpy-win64-v5.0.1/` 中的完整官方组件，手机需授权调试 |

热点内的画面传输不依赖外网，但红果加载短剧仍需要移动数据或其他互联网连接。手机助手的 APK 虽允许安装到部分较早系统，共享功能仍要求 Android 14+；没有「单个应用」选项时请取消授权，不用整屏共享替代。

**从 GitHub 克隆仓库或下载并解压完整 ZIP 后，可直接启动，无需编译或手动补齐运行依赖。** 仓库已包含电脑程序、手机 APK、FFmpeg 和 scrcpy。仅需自行修改源码或运行开发检查时，按[编译与检查](#编译与检查)准备构建环境。

## 启动与安装

### 电脑端

1. 将软件保存在独立文件夹中，保留 `bin/`、`tools/` 和启动脚本的相对位置，不要单独移动 exe。
2. 双击根目录的 `启动红果遥控端.cmd`。也可以直接打开 `bin/HongguoRemote.exe`。
3. 启动脚本或成功执行 `build.ps1` 后，会创建／更新当前用户桌面的「红果遥控端」快捷方式，之后可从桌面启动。

启动脚本通过 `build.ps1 -Launch` 打开程序，不会自动编译。提示程序不存在时，需先构建。仅下载、解压、Git 拉取或直接打开 exe 不会创建快捷方式。移动软件文件夹后，重新运行启动脚本即可更新快捷方式路径；创建快捷方式失败会显示警告，不影响已有程序启动。

### 手机端

1. 把 `bin/HongguoCompanion.apk` 传到手机，按手机系统提示允许本次来源安装，安装「红果手机助手」。这是本地签名测试版，不是应用商店发行版。
2. 打开手机助手。只需观看时可以跳过电脑控制权限；需要鼠标点击和滑动时，在系统无障碍设置中启用「红果手机助手 · 电脑控制」。
3. 若侧载应用被提示「受限制的设置」，按手机系统指引到应用信息页允许相关设置，再返回无障碍设置。不同系统的入口不同，电脑端不会代为修改权限。

无障碍权限通常只需首次开启；被系统撤销后需重新开启。服务连接较慢时，可继续等待或先选择「仅观看」。

## 手机助手连接（推荐）

### 首次连接

1. **接入同一网络。** 推荐在手机开启热点，让电脑连接该热点；也可以让两端连接同一 Wi-Fi。
2. **设置声音。** 在手机助手按需勾选「声音传到电脑」。开启后系统可能请求录音权限，这是应用播放音频捕获所需权限，不采集麦克风；拒绝后仍可共享画面。
3. **开始共享。** 手机点击「开始共享」。未开启电脑控制时，选择去开启权限或「仅观看」。
4. **授权单个应用。** 在安卓系统弹窗中选择「单个应用 → 红果短剧」，返回助手后点击「已选择红果短剧」确认。误选其他应用或整屏时请取消并重新授权；系统未向助手提供核验所选应用身份的接口，需要自行确认。
5. **电脑发现手机。** 点击「查找并连接手机」。只发现一台时进入连接流程；发现多台时选择目标，再点「开始投屏」。
6. **手机批准连接。** 检查助手弹窗中的电脑名称和局域网地址，确认是刚操作的电脑后点「允许本次」。
7. **打开红果播放。** 在手机上打开红果短剧，电脑等待画面出现。已启用电脑控制时，可在画面内点击、拖动操作。

每次新的共享都需要安卓的屏幕捕获确认；每次电脑连接都需要手机同意。一次只接受一台电脑，未批准前不传输画面和音频。

### 日常使用与结束

- 连接成功后左侧面板自动收起，点击底部「连接与设置」可重新展开。窄窗口时面板会覆盖画面，收起后继续观看。
- 手机切到其他应用或锁屏时，可能显示等待并暂停声音；共享仍有效时，回到红果可在同一连接上恢复。仅观看模式依据系统报告的共享内容可见状态暂停／恢复；开启控制后还会检查红果前台状态。
- 电脑点击「结束投屏」断开本次连接；手机助手内、通知或系统共享提示可停止共享，停止后连接立即失效。
- 网络中断后，检查手机是否仍在共享，再重新「查找并连接手机」并在手机允许。如果已停止共享，先重新执行共享授权。
- 关闭电脑程序会结束本程序的投屏，不退出手机上的红果，也不关闭其他工具使用的 ADB 服务。

### 声音与画质

手机助手模式的声音开关在**手机端**。电脑「USB / 调试模式转发声音」和清晰度下拉框仅影响原调试模式。需要修改手机声音选项时，停止共享后重新设置并共享。

音频捕获限定红果应用。手机捕获到有效声音后才尝试静音；若静音后持续捕获不到声音，会恢复手机音量，本次共享保留手机声音。断开时恢复原音量，但你手动改过音量时保留手动设置。电脑音量通过 Windows 系统音量调节。应用可能禁止声音捕获，受保护视频也可能黑屏，不能绕过这些限制。

手机助手使用 H.264 硬件编码，尽量保持原画比例，不放大小尺寸源画面；最长边上限 3200、最短边上限 1440。依次尝试 120、90、60、30 帧，并根据硬件能力和启动结果降低尺寸或帧率。码率目标为 6–32 Mbps，实际受编码器能力限制；VBR 不保证瞬时流量上限。

电脑用 `tools/ffmpeg/ffmpeg.exe` 解码，观看栏显示接收、解码和播放帧率。目标 120 帧不等于实际达到 120 帧；源画面、手机采集与编码、网络、电脑性能及显示器刷新率都会影响结果。播放帧率表示向 WPF 提交画面的次数，不能代替屏幕实际扫描帧率，也不表示源视频有相同数量的独立内容帧。高刷新率显示还需在 Windows 中启用对应刷新率。

## 画面操作与全屏

| 操作 | 用法及范围 |
| --- | --- |
| 鼠标点击／拖动 | 触摸／滑动手机画面；手机助手模式需已授权电脑控制 |
| ↑／↓与滚轮 | 观看快捷操作，发送上下滑动，不保证红果切换下一集 |
| 键盘方向键 | 手机助手模式需开启「启用画面内键盘操作」，并先点击画面获得焦点 |
| F11／「全屏」 | 主窗口全屏，未连接时也可使用 |
| Esc／「退出全屏」 | 恢复全屏前的窗口尺寸与状态 |
| 搜索、选集、收藏、暂停 | 点击手机原有界面上的对应按钮 |
| 手机助手文字输入 | 当前电脑界面未提供文字输入入口，搜索文字请在手机输入 |
| USB／调试模式中文粘贴 | 电脑复制文字，手机输入框聚焦后尝试 Ctrl+V；输入法兼容性需实机验证 |

「启用画面内键盘操作」不是手机助手模式的通用电脑文字输入开关。搜索、列表或输入场景可关闭该选项，避免方向键误滑；当前手机助手模式的鼠标滚轮不受此开关控制，仍会发送滑动，请避免误滚。投屏不自动读取手机剪贴板。

全屏会隐藏头部、底部和连接面板，保留退出按钮，画面等比缩放。原调试模式尝试嵌入主窗口；若 Windows 不允许嵌入，会保留独立的「红果实时画面」窗口，可在该窗口使用 scrcpy 的 Alt+F 全屏。

### 画面裁剪

此功能仅用于手机助手模式，不改变手机实际采集范围，点击坐标会换算回原始画面。

1. 连接手机并等待有效画面。首次进入全屏（F11）时，默认采样约 2.4 秒检测连续黑边，随后显示静态预览。
2. 检查预览，满意后点击「保存裁剪」才会应用并保存。
3. 不满意时选择「手动裁剪」，在完整画面中拖动框选需要保留的区域，再预览或保存。
4. 点击底部「画面裁剪 / 重新裁剪」可重新检测。要取消裁剪，选择「恢复完整画面」后再保存。

取消预览会保留原设置，本次运行不再因全屏反复弹出；已有保存设置时，重启后也不会自动弹出。设置位于 `bin/crop.txt`，重启自动沿用；画面宽高比改变时暂用完整画面，需要重新裁剪。

暗场、黑边字幕和按钮会影响检测结果，请检查预览。裁剪后仍等比显示，竖屏画面在横屏显示器上可能继续留有左右空白。原 USB / scrcpy 模式不应用此裁剪。

## USB 与无线调试（可选）

以下操作属于「高级连接」，使用手机助手模式时无需执行。切换连接方式前先「结束投屏」。调试模式使用整屏投屏，不具备手机助手的单应用共享范围。

### USB 连接

1. 准备完整的 scrcpy 依赖，见[投屏依赖](#投屏依赖)。
2. 手机开启开发者选项和 USB 调试，用支持数据传输的数据线连接电脑。
3. 解锁手机，在调试授权弹窗中允许这台电脑。
4. 电脑展开「高级连接」，点「刷新调试设备」，选择已就绪的 USB 设备。
5. 手机打开红果，电脑点击「开始投屏」。

小米／红米若能看不能点，请检查「USB 调试（安全设置）」。红米 K70 可在「设置 → 我的设备 → 全部参数与信息」连续点击 OS / MIUI 版本开启开发者模式，再到「更多设置 → 开发者选项」开启 USB 调试。不需要 OEM 解锁。没有 USB 提示时先换数据线或 USB 口。

电脑的「流畅 · 1280 / 4 Mbps」「清晰 · 1920 / 8 Mbps」及声音复选框用于此模式；当前启动参数限制最高 60 帧。

### 自动发现无线调试设备

需要手机支持 Android 11+ 无线调试，两端在同一可互通网络：

1. 手机开启无线调试，进入「使用配对码配对设备」，保持页面打开。
2. 电脑在「高级连接」点击「使用原来的无线调试连接」。多台设备时先选择目标。
3. 输入手机显示的 6 位码，点「配对并连接」。程序会尝试查找同一手机的连接服务；已连接设备可直接识别。
4. 设备就绪后，打开红果，点「开始投屏」。

自动查找使用 ADB mDNS。没有广播时，仅检查当前 Wi-Fi 的唯一 IPv4 网关的 5555 端口，不扫描其他设备或端口。广播隔离、仅 IPv6 服务或手机要求先连接 Wi-Fi 时，自动发现可能失败；电脑无法绕过手机系统限制。

### 手动配对与连接

1. 手机打开无线调试的配对码弹窗。
2. 电脑「配对地址（配对码弹窗）」填写该弹窗的 `IPv4:端口`，填写 6 位码，点击「配对手机」。
3. 回到手机无线调试**主页面**，将该页的 `IPv4:连接端口` 填到电脑「连接地址（无线调试主页面）」，点「连接无线设备」。
4. 选中已就绪的无线设备，再开始投屏。

例如 `192.168.1.8:37123` 只是地址格式示例，必须使用手机当前显示的值。配对端口与连接端口通常不同，不能混用。程序不保存配对码；换网络或端口变化后需重新发现或更新地址。

### 先 USB 再转无线

1. 先完成 USB 连接与授权，选择 USB 设备，并结束投屏。
2. 点「USB 转无线（端口 5555）」。
3. 在连接地址中填写手机当前局域网 `IP:5555`，点「连接无线设备」。热点模式可在电脑网络详情查看默认网关；同一 Wi-Fi 时查看手机 Wi-Fi 详情中的地址。
4. 连接成功并选中无线设备后，再拔掉 USB 开始投屏。
5. 用完结束投屏，选择相应设备，点击「关闭 5555，恢复 USB 模式」。Android 的无线调试开关需另在手机设置中关闭。

仅在自己的热点或可信网络使用调试连接。断线后先恢复网络，刷新设备再开始投屏，程序不会自动操作手机。

## 常见问题与运行日志

| 现象 | 排查方法 |
| --- | --- |
| 启动提示找不到程序 | 确认下载并解压了完整项目且 `bin/HongguoRemote.exe` 存在；文件缺失时重新获取完整项目或自行构建，启动脚本不会自动构建 |
| 缺少解码／投屏组件 | 手机助手模式检查 `tools/ffmpeg/ffmpeg.exe`；调试模式检查完整 scrcpy 目录，不要只复制 exe |
| 查找不到手机助手 | 确认手机已开始共享、两端同一网络且允许局域网互通；检查手机状态及 Windows 防火墙是否阻止程序通信 |
| 电脑一直等待授权 | 回手机助手查看连接请求，确认电脑后允许；拒绝或连接超时后重新查找 |
| 手机没有单应用共享选项 | 检查 Android 版本和系统更新；没有该选项时取消，不选整屏替代 |
| 有画面但不能操作 | 手机助手检查无障碍服务与红果前台状态；仅观看无法控制。调试模式检查调试授权和厂商安全设置 |
| 输入文字无反应 | 当前手机助手电脑界面没有文字输入入口，请在手机输入；调试模式粘贴需输入框聚焦 |
| 无声音或手机未静音 | 检查手机「声音传到电脑」、音频权限、Windows 音量与红果是否允许捕获；停止共享后关闭声音转发可继续仅看画面 |
| 黑屏／切出后等待 | 回到红果并解锁手机；检查是否选错共享应用。受保护内容可能无法捕获 |
| 卡顿、帧率较低 | 对照接收／解码／播放帧率，检查热点信号、设备性能和刷新率；调试模式可选流畅档，手机助手画质自动适配 |
| 裁剪误删字幕或按钮 | 重新裁剪，手动扩大保留区域，或恢复完整画面并保存 |
| APK 更新提示签名不一致 | 使用原签名重新构建；不同签名无法覆盖安装。不要直接删除旧安装或签名文件来处理 |

### 导出日志

1. 先复现问题。
2. 电脑底部点「运行日志」，点「刷新日志」读取最新记录。
3. 点「导出日志…」保存文本，检查内容后再提供给开发者，并说明手机型号、系统版本、连接方式和复现步骤。
4. 程序无法启动时，直接查看软件根目录的 `logs/`。

日志关闭程序后保留，当前文件为 `logs/current.log`，另保留两份历史文件，每个文件最多约 1 MiB。保存失败时会提示原因并提供本次内存记录，仍可导出。

日志记录运行环境、连接、投屏、解码状态和错误详情，不主动采集输入文字、配对码或音视频；会隐藏协议文字输入内容、六位数字及当前用户目录。日志仍可能包含手机名称、局域网地址及第三方错误文本，发送前请检查。日志不会自动上传。

性能样本还包含源时间戳帧率、跳帧、合成器忙次数和提交耗时等，可辅助定位问题；这些数值不能单独证明手机真实画质、屏幕输出帧率或音画同步效果。

## 更新、数据与卸载

### 更新与备份

- 更新时退出电脑程序，并同时更新电脑端和手机 APK，保留完整 `tools/` 目录。
- 手机 APK 使用同一签名覆盖安装。自行构建时务必备份 `tools/companion-local.p12`，后续更新需用同一签名；不要提交或公开私钥。
- `bin/crop.txt` 为裁剪设置，`logs/` 为运行记录；需要保留时先备份。移动软件后重新运行启动脚本以更新桌面快捷方式。

### 卸载电脑端

先退出程序，再运行根目录 `uninstall.exe`（由 `build.ps1` 生成）。确认窗口会显示待删除的完整路径，默认取消。

**确认卸载会永久删除整个软件文件夹**，包括源码、依赖、日志、本地签名及自行放入的文件，请提前备份。不要把软件直接放在桌面、用户目录等公共目录根部。

卸载器只删除指向当前目录的桌面「红果遥控端」快捷方式；手机助手需在手机上另行卸载。目录包含链接或联接时会停止卸载，文件占用或权限不足时会报告失败，应检查剩余文件。

## 编译与检查

所有命令默认在项目根目录执行。电脑端使用 Windows 自带的 .NET Framework C# 编译器，不需要 .NET SDK 或 NuGet。安卓端使用 Java 17 与官方 Android SDK，不依赖 Gradle、第三方安卓运行库或云端构建。

### 准备构建依赖

| 依赖 | 准备方式与预期位置 |
| --- | --- |
| .NET Framework | Windows x64 下的 `Microsoft.NET/Framework64/v4.0.30319/csc.exe`，并具备项目所需 WPF 程序集 |
| Java 17 | `java`、`javac`、`jar`、`keytool` 可在 PowerShell 中运行 |
| Android API 35 | 从[官方 Android SDK](https://developer.android.com/tools)准备 `android.jar`，放到 `tools/android-sdk/android-35/android.jar` |
| Android Build Tools 35 | 将完整工具内容放到 `tools/android-sdk/android-15/`，包括 `aapt2.exe`、`zipalign.exe`、`lib/d8.jar`、`lib/apksigner.jar` |
| FFmpeg Windows 构建 | 从 [FFmpeg 下载入口](https://ffmpeg.org/download.html)获取，保留构建所需运行文件，可执行文件为 `tools/ffmpeg/ffmpeg.exe` |
| scrcpy（可选调试模式） | 按下文固定版本和目录准备 |

`android-15` 是当前安卓构建脚本使用的目录名，其中放的是 **Build Tools 35**，不要按目录名误放其他版本。FFmpeg 用于运行和视频测试，scrcpy 用于原调试模式；它们不是电脑 C# 编译依赖。

### 构建电脑程序与手机 APK

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\android\build.ps1
```

电脑构建生成 `bin/HongguoRemote.exe`、根目录 `uninstall.exe` 并尝试更新桌面快捷方式。安卓构建生成 `bin/HongguoCompanion.apk`，执行签名校验；首次构建会创建本机签名 `tools/companion-local.p12`。请妥善保管，不要上传到公开仓库。

两个脚本分别构建两端，不会互相代为构建。源码、依赖与构建产物应按现有相对路径保存。

### 运行现有回归检查

电脑测试：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\run.ps1
```

该脚本编译 `tests/out/Tests.exe` 并运行检查，覆盖设备解析、参数验证、协议和视频解码等。完整 TLS 检查需要先运行安卓构建生成本地证书，并在正常 Windows 用户环境执行；受限环境中的 Schannel 可能因凭证不可用失败。

测试可执行文件编译完成后，可单独运行视频解码与阻塞恢复检查，不依赖 TLS 检查环境，但仍需要 FFmpeg：

```powershell

```

完成电脑构建后，运行裁剪与相关显示检查：

```powershell
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\tests\CropTests.ps1
```

完成安卓构建后，使用 Java 17 检查发送超时、编码能力选择和触摸区域映射。先确保测试输出目录存在：

兼容测试使用构建后的生产类和合成能力数据；Android SDK jar 只用于加载类型，不调用真实安卓运行时 API。能力测试、模拟 TLS 和合成视频解码通过，均不能代替手机实机验收。

## 兼容性与验证范围

项目已有设备解析、协议校验、TLS 模拟、真实 H.264 解码及阻塞恢复、黑边检测、裁剪坐标映射、编码尺寸约束和发送超时等检查。旧 README 记录了两端构建、APK v3 签名及多项回归结果，同时记录了受限 Windows 环境的 TLS 凭证问题；这些是历史记录，不表示本次文档修改重新执行或通过了所有检查。

各品牌当前版本的完整实机兼容性仍需确认。小米／红米应重点检查受限制设置和热点发现，OPPO／一加检查权限返回与共享启停，vivo 检查后台限制和重连，三星检查横竖屏及折叠切换，荣耀检查触摸位置、声音与音量恢复。不能把编码器能力检查通过视为整机兼容通过。

建议实际使用或更新后按以下顺序验收：

1. 安装、按需授权控制、开始单应用共享、热点发现。
2. 拒绝电脑连接一次，再重新连接并允许；打开红果，检查观看及点击／滑动。
3. 切出红果、返回红果、锁屏和解锁，检查等待、清屏停声与恢复。
4. 检查声音转发、手机静音和断开后的音量恢复。
5. 检查横竖屏、F11／Esc、自动／手动裁剪及恢复完整画面。
6. 手机停止共享、重新授权连接，连续播放 30 分钟并查看性能日志。
7. 需要调试模式时，另外验收 USB、无线配对及恢复 USB 模式。

## 隐私与连接安全

配套模式使用 UDP 24680 回复局域网发现请求，TCP 24681 通过 TLS 1.2 传输；电脑核对发现响应中的证书指纹。首次身份发现依赖当前局域网及手机上的连接确认，没有云端账户认证，请在自己的热点或可信网络使用。

屏幕、音频和控制内容不上传服务器。无障碍用于已授权的红果控制，音频仅捕获红果播放声音；单应用共享内容需在系统弹窗中自行选对。调试模式是整屏投屏，可能显示手机其他界面。需要停止时，在手机端停止共享或在电脑结束投屏。
